# Mobile-Ansicht – Implementation Plan

**Status:** Accepted (2026-11-23)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Meta-Analyse und Einzelanalyse sind auf 360–430 px breiten Handys ohne seitliches Scrollen voll nutzbar.

**Architecture:** Hauptsächlich Media Queries (`max-width: 640px`) am bestehenden Markup. Zusätzlich gibt es:
- einen Filter-Button mit Panel-Schaltung (Klasse am `#loader-panel`) in js/main.js,
- eine Kurzform der Statuszeile und eine Sortierauswahl der Partienliste in metaController.js und metaView.js,
- eine Tipp-Variante des gemeinsamen Tooltips.

Die Partienliste entsteht per CSS-Grid aus den vorhandenen Tabellenzellen.

**Tech Stack:** Vanilla JS, Tailwind-CDN plus `css/styles.css`. Geprüft wird mit Headless-Chrome über das DevTools-Protokoll (PowerShell, Windows).

**Spec:** `docs/superpowers/specs/2026-11-23-mobile-design.md`

## Global Constraints

- Handy-Breakpoint: `@media (max-width: 640px)`. Regeln über 640 px ändern sich nicht. Ausnahme ist `min-width: 0` an Grid- und Flex-Kindern, das am Desktop keine Wirkung hat.
- Der Desktop (1400 px) sieht nach jedem Task unverändert aus. Das wird per Screenshot-Vergleich mit dem Stand vor dem Task geprüft.
- Es entsteht kein doppelter Darstellungscode pro Tab.
- Branch `mobile`, ein Commit pro Task.

## Review Focus

1. **Lange Inhalte ohne Umbruchstelle:** z. B. lange Gegnernamen, Eröffnungsnamen oder E-Mail-artige Nutzernamen. Sie dürfen die Seite nicht verbreitern (Ellipse oder Umbruch). Geprüft wird per Überlauf-Check in jedem Tab (Task 1, Schritt 3).
2. **Popup-Menüs der Filter am rechten Rand:** Sie liegen innerhalb des Bildschirms. Geprüft wird in Task 2, Schritt 4.
3. **Tooltip per Tippen in Tabellenzeilen:** Ein Tippen auf die Tooltip-Zelle zeigt den Tooltip, ein Tippen auf eine andere Zelle öffnet die Partie. Geprüft wird in Task 6, Schritt 3.
4. **Fensterbreite 360 px, also die kleinsten Handys:** Auch dort darf nichts überlaufen. Geprüft wird per Überlauf-Check mit Breite 360 (Task 1, Schritt 3).
5. **Desktop-Regression durch `min-width: 0`:** Geprüft wird per Screenshot-Vergleich bei 1400 px (Task 1, Schritt 4).

### Task 1: Prüfwerkzeug, Überlauf-Ursache, einspaltige Kacheln

**Files:**
- Create: `scripts/mobile-check.ps1`
- Modify: `css/styles.css`

**Interfaces:**
- Produces: `scripts/mobile-check.ps1 -Width <int> -Out <dir> [-Url] [-User geieruno]`. Das Skript öffnet die App im Headless-Chrome mit Handy-Emulation, klickt jeden Meta-Tab an und gibt pro Tab `tab: scrollWidth/clientWidth` sowie die Top-5-Elemente aus, die über den rechten Rand ragen. Pro Tab legt es einen Screenshot `<tab>.png` (Viewport) ab. Ist `-Url` ein Deep-Link, nimmt es die Einzelanalyse auf (`game.png`). Exit-Code 1, wenn irgendwo `scrollWidth > clientWidth`.

- [ ] **Schritt 1:** `mobile-check.ps1` schreiben. Es ist eine Weiterentwicklung der Scratchpad-Skripte `shot.ps1` und `cdpm.ps1`, mit Port 9336 und eigenem Profil unter `%TEMP%`.
- [ ] **Schritt 2:** Ausführen mit `-Width 390`. Erwartet: Exit 1 und Überlauf in allen Tabs (heute `scrollWidth=742`).
- [ ] **Schritt 3:** Überlauf beheben. `#meta-content > *`, `.meta-grid > *` und Flex-Kinder bekommen `min-width: 0`. Unter 640 px werden Statuszeile, Kachelköpfe und KPI-Raster umbruchfähig. Die KPIs stehen zweispaltig (`repeat(2, minmax(0,1fr))`), alle Kacheln einspaltig. `mobile-check.ps1 -Width 390` und `-Width 360` ausführen. Erwartet: Exit 0, abgesehen von der Filterleiste, die bleibt bis Task 2. Bis dahin ist `#loader-panel` vom Check ausgenommen und das als Ruling im Ledger vermerkt.
- [ ] **Schritt 4:** Desktop-Vergleich: Screenshots bei 1400 px vor und nach dem Task. Erwartet: keine sichtbare Änderung.
- [ ] **Schritt 5: Commit** `Mobile: kein seitliches Scrollen, Kacheln einspaltig`

- [ ] **Schritt 1:** Button anlegen: Filter-Icon plus Zähler. Er ist nur unter 640 px und nur im Meta-Modus sichtbar.
- [ ] **Schritt 2:** Unter 640 px sind Zeitraum, Spielart, Ergebnis, Farbe, Gegner und „Spiele laden“ ohne `filters-open` ausgeblendet. - [ ] **Schritt 3:** Zähler laut Spec. Er aktualisiert sich bei jeder Filteränderung, dafür hängt er an der vorhandenen Stelle, an der Filteränderungen `meta?.…` neu rendern. Das Panel schließt nach „Spiele laden“ und beim Tab-Wechsel.
- [ ] **Schritt 4:** Popup-Menüs, die über den rechten Rand ragen, werden per `max-width` und `right: 0` in den Bildschirm geholt. Prüfung: `mobile-check.ps1` mit dem Schritt „Filter-Button klicken, Spielart-Menü öffnen“ (Screenshot `filters.png`) bei 360 und 390. Erwartet: Exit 0 inklusive `#loader-panel`, das Menü liegt sichtbar im Bild.

### Task 3: Statuszeile kurz, Tabs wischbar

- [ ] **Schritt 1:** `renderStatus` gibt zusätzlich eine Kurzform in `<span class="meta-status-short">` aus: „{n}/{total} Partien · [{have}/{have+missing}] Engine“, mit dem farbigen `.meta-cov`-Kästchen. Unter 640 px ist die Langform ausgeblendet und die Kurzform sichtbar, darüber umgekehrt. Die Spielart-Zahlen dürfen umbrechen.

- [ ] **Schritt 4:** `mobile-check.ps1` bei 360 und 390 inklusive Screenshot `games.png`. Erwartet: Exit 0, Zeilen zweizeilig lesbar, Sortierung wirkt. Desktop-Vergleich (Tabelle unverändert).

### Task 6: Tooltips per Antippen

**Files:** `js/meta/metaController.js` (Tooltip-Logik)

- [ ] **Schritt 1:** Auf `(hover: none)` öffnet ein `click` auf ein Element mit `data-tip`, `data-opening` oder `data-mate` den Tooltip, über dieselbe Funktion wie `mousemove`, positioniert am Element. Ist der Tooltip für genau dieses Element schon offen, läuft die normale Aktion. Sonst werden `preventDefault` und `stopPropagation` aufgerufen, damit sich die Zeile nicht öffnet. Ein Tippen daneben oder Scrollen schließt ihn.
- [ ] **Schritt 2:** Klicks auf `.meta-count`, `[data-analyze]` und Sortier-Elemente behalten ihre Aktion sofort, auch wenn sie einen `data-tip` tragen.
- [ ] **Schritt 3:** Prüfung im Headless-Modus mit Touch-Emulation, Tab „Partien“:
  - Tippen auf die Ergebniszelle zeigt den Tooltip und öffnet nicht (`window.open` abgefangen).
  - Tippen auf die Gegnerzelle öffnet bzw. zeigt das Hinweis-Popover.
  - Im Tab „Matt“ zeigt ein Tippen auf ein Mattbild das Brett.
- [ ] **Schritt 4: Commit** `Mobile: Tooltips per Antippen`
